# 草稿会话到正式会话过渡动效计划

## 背景

当前草稿会话和正式会话是两个明显不同的界面状态：

- 草稿态：输入框居中，显示标题“告诉 Codex 需要构建什么？”，输入框下方显示项目切换选项。
- 正式态：输入框固定在底部，项目切换选项消失，顶部/中部出现用户消息和 AI 等待或回复消息。

现在切换过程偏硬切，缺少“从输入到对话流”的连续感。目标是在用户从草稿态发送第一条消息后，做一段自然的状态过渡。

## 目标动效

从草稿会话切换到正式会话时：

1. 输入框整体从草稿态的居中位置向下移动，过渡到正式会话底部输入框位置。
2. 输入框下方的项目切换选项跟随输入框移动，并在移动过程中逐渐淡出，最终消失。
3. 标题“告诉 Codex 需要构建什么？”向上移动，同时逐渐淡出，最终消失。
4. 用户消息和 AI 等待/回复消息从下方向上进入，同时从半透明变为不透明。
5. 整体观感应是“草稿输入提交后，界面让位给正式对话流”，而不是两个界面瞬间替换。

## 状态边界

- 只针对“0 会话/草稿会话发送第一条消息后进入正式会话”的过渡。
- 普通正式会话内继续发送消息，不使用这套整屏过渡。
- 切换已有正式会话时，不触发草稿到正式会话动效。
- 切换项目导致进入另一个草稿会话时，应保持草稿态，不播放正式化过渡。
- 用户刷新页面后直接加载正式会话，不补播过渡。

## 实施思路

1. 在前端状态中记录一次性过渡标记，例如 `draftTransitionThreadId`。
2. 在草稿态发送第一条消息并创建真实 thread 后，设置该标记。
3. `Composer` 或外层布局根据该标记进入 `draft-transitioning` 状态。
4. CSS 中为以下元素补过渡类：
   - 草稿标题：上移 + 淡出。
   - 草稿输入容器：从居中位置移动到底部输入区位置。
   - 项目切换选项：随输入容器移动 + 淡出。
   - 新出现的用户消息和 AI 等待消息：下方进入 + 淡入。
5. 动画结束后清除一次性过渡标记，界面进入普通正式会话状态。

## CSS/交互原则

- 优先使用 `transform` 和 `opacity`，避免频繁触发布局重排。
- 输入框移动过程中尺寸不要跳变；必要时使用固定/稳定的宽度约束。
- 动画时长建议先控制在 `260ms - 380ms`。
- easing 建议使用柔和但不拖沓的曲线，例如 `cubic-bezier(.2,.8,.2,1)`。
- 不要影响正式会话内消息列表滚动性能。
- 需要支持深色/浅色和自定义主题，不写死背景色。

## 验证点

- 从草稿态发送第一条消息后，项目切换选项淡出，不应闪烁或突然跳走。
- 标题上移淡出，不应遮挡消息。
- 输入框落到底部后位置应与正式会话一致。
- 用户消息和 AI 等待消息应从下方淡入，不应突然出现在旧位置。
- 已有正式会话继续发送消息，不应触发整屏过渡。
- 刷新正式会话页面，不应补播草稿过渡。
- 快速切换项目/会话时，不应残留过渡类或隐藏项目切换控件。

## 暂不处理

- 不重做消息气泡布局。
- 不重构 Composer 业务功能。
- 不处理置顶相关 bug；置顶问题在后续单独修。
